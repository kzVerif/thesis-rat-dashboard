# คู่มือการใช้งาน RAT System Dashboard

> Production HTTPS/WSS configuration: see [Transport Security](docs/transport-security.md) and [.env.example](.env.example). Production build/start validates these settings.

เอกสารฉบับนี้จัดทำสำหรับผู้ที่เปิดใช้งานระบบเป็นครั้งแรก โดยอธิบายตั้งแต่การเปิดระบบ การเข้าสู่ระบบ การอ่านข้อมูล ไปจนถึงการจัดการเครื่อง การสั่งสแกนไวรัส การกระจายไฟล์ และการตรวจสอบประวัติการใช้งาน

> **ชื่อระบบ:** RAT System — Remote Administration  
> **กลุ่มผู้ใช้เป้าหมาย:** ผู้ดูแลระบบหรือผู้ปฏิบัติงานที่ได้รับอนุญาต  
> **บัญชี Seed สำหรับทดสอบ:** `admin` / `password123`

## 1. ระบบนี้ใช้ทำอะไร

RAT System Dashboard เป็นหน้าจอศูนย์กลางสำหรับดูแลเครื่องคอมพิวเตอร์หลายเครื่องที่มีโปรแกรม Agent ติดตั้งอยู่ ระบบช่วยให้ผู้ดูแลสามารถ

- ดูภาพรวมจำนวนเครื่อง ห้อง ผู้ใช้งาน Token และกิจกรรมล่าสุด
- จัดกลุ่มเครื่องไว้ในห้อง เช่น ห้องเรียน ห้องปฏิบัติการ หรือแผนก
- ตรวจสอบสถานะและข้อมูลเครือข่ายของ Agent แต่ละเครื่อง
- ดูภาพหน้าจอของเครื่องแบบสดในโหมดดูอย่างเดียว (View-only)
- สั่งตรวจไวรัสให้ทั้งห้องหรือเลือกเป็นรายเครื่อง
- จัดเก็บไฟล์ส่วนกลางและส่งไฟล์ไปยังเครื่องหรือทั้งห้อง
- ตรวจสอบผลการกระจายไฟล์และรายละเอียดรายเครื่อง
- จัดการบัญชีผู้ใช้ บทบาท และสิทธิ์
- สร้าง Enrollment Token สำหรับใช้ลงทะเบียน Agent
- ตรวจสอบ Audit Logs ซึ่งเป็นประวัติการเปลี่ยนแปลงและเหตุการณ์สำคัญ

ระบบนี้เป็นเครื่องมือบริหารจัดการระยะไกล ควรใช้งานเฉพาะเครื่องและผู้ใช้ที่องค์กรเป็นเจ้าของหรือได้รับอนุญาตเท่านั้น

## 2. สิ่งที่ต้องเตรียมก่อนใช้งาน

### 2.1 สำหรับผู้ใช้งานทั่วไป

ต้องมีสิ่งต่อไปนี้

1. เครื่องคอมพิวเตอร์ที่ใช้เปิดเว็บเบราว์เซอร์ เช่น Chrome, Edge หรือ Firefox
2. URL ของ Dashboard จากผู้ดูแลระบบ
3. ชื่อผู้ใช้และรหัสผ่านที่ถูกต้อง
4. การเชื่อมต่อเครือข่ายไปยัง Dashboard และ Backend

ถ้าต้องการดูหน้าจอ สั่งสแกน หรือกระจายไฟล์ เครื่องปลายทางต้องมี Agent ที่เชื่อมต่อกับระบบ และ Agent ต้องอยู่ในสถานะที่พร้อมทำงาน

### 2.2 สำหรับผู้ดูแลหรือผู้ติดตั้งระบบ

โปรเจกต์นี้เป็น Next.js application และต้องมี Backend ที่กำหนดในตัวแปร `API_URL` รวมถึง WebSocket ที่กำหนดใน `NEXT_PUBLIC_FRONTEND_WS_URL` สำหรับฟังก์ชันแบบเรียลไทม์ เช่น ดูหน้าจอ กระจายไฟล์ และ AV Scan

ในโฟลเดอร์โปรเจกต์ ให้ติดตั้งแพ็กเกจและเริ่มระบบดังนี้

```bash
npm install
npm run dev
```

จากนั้นเปิด `http://localhost:3000` หากต้องการรันแบบ Production ให้ใช้

```bash
npm run build
npm start
```

การเริ่มหน้าเว็บได้สำเร็จไม่ได้แปลว่า Backend หรือ Agent พร้อมใช้งานเสมอไป หากข้อมูลไม่ขึ้น ให้ตรวจการเชื่อมต่อ Backend และ WebSocket ด้วย

## 3. การเข้าสู่ระบบครั้งแรก

1. เปิด URL ของ Dashboard
2. ที่หน้า **ยินดีต้อนรับกลับมา** ให้กรอกช่อง **ชื่อผู้ใช้งาน** เป็น `admin`
3. กรอกช่อง **รหัสผ่าน** เป็น `password123`
4. หากต้องการตรวจสอบรหัสผ่านก่อนส่ง ให้กด **แสดง** ข้างช่องรหัสผ่าน กดอีกครั้งเพื่อซ่อน
5. กด **เข้าสู่ระบบ**
6. เมื่อสำเร็จ ระบบจะพาไปหน้า **แดชบอร์ด**

ข้อมูลบัญชีสำหรับทดสอบ

| รายการ | ค่า |
|---|---|
| Username | `admin` |
| Password | `password123` |

คำแนะนำด้านความปลอดภัย: บัญชีนี้เป็นรหัสเริ่มต้นที่ถูกระบุไว้สำหรับ Seed ควรเปลี่ยนรหัสผ่านทันทีหลังเข้าใช้งานจริง โดยไปที่เมนูบัญชีด้านล่างซ้าย > **ตั้งค่า** > เปลี่ยนรหัสผ่าน และไม่ควรส่งรหัสผ่านผ่านแชตหรือเอกสารที่บุคคลอื่นเข้าถึงได้

หากเข้าสู่ระบบไม่สำเร็จ ให้ตรวจว่าพิมพ์ตัวเล็ก-ใหญ่ถูกต้อง ไม่มีช่องว่างติดท้าย และระบบ Backend ยังทำงานอยู่ ถ้าระบบขึ้นว่าเชื่อมต่อไม่ได้ ให้ตรวจเครือข่ายก่อนลองใหม่

## 4. ส่วนประกอบของหน้าจอ

หลังเข้าสู่ระบบจะเห็นหน้าหลักสองส่วน

- **แถบเมนูด้านซ้าย:** ใช้เปลี่ยนไปยังงานแต่ละประเภท หากหน้าจอแคบ แถบเมนูอาจถูกย่อ ให้กดปุ่มเมนูด้านบนเพื่อเปิดหรือปิด
- **พื้นที่ทำงานด้านขวา:** แสดงตาราง การ์ด แบบฟอร์ม และปุ่มของหน้าที่เลือก

ด้านล่างสุดของแถบเมนูจะแสดงชื่อบัญชีที่กำลังใช้งาน เมื่อกดบริเวณชื่อบัญชีจะมีเมนู **ตั้งค่า** และ **ออกจากระบบ**

ก่อนปิดเบราว์เซอร์หรือเลิกใช้เครื่องที่เป็นเครื่องสาธารณะ ให้กด **ออกจากระบบ** เสมอ การออกจากระบบจะยกเลิก Session ของเครื่องปัจจุบัน ส่วน **ออกจากระบบทุกอุปกรณ์** ในหน้า Settings จะยกเลิก Session ของทุกอุปกรณ์

## 5. เมนูทั้งหมดโดยสรุป

| เมนู | ใช้สำหรับ | งานที่ทำบ่อย |
|---|---|---|
| แดชบอร์ด | ดูภาพรวมระบบ | ตรวจจำนวนเครื่องและกิจกรรม |
| ห้องเรียน | จัดกลุ่มเครื่อง | เพิ่ม แก้ไข ลบห้อง |
| Agents | จัดการเครื่องที่ติด Agent | ค้นหา แก้ชื่อ ย้ายห้อง ดูรายละเอียด |
| ตรวจสอบหน้าจอ | ดูหน้าจอเครื่อง | เลือกห้องแล้วดูภาพแบบ View-only |
| สั่ง AV Scan | สั่งสแกนไวรัส | เลือกแบบสแกนและเป้าหมาย |
| ติดตามผลการสแกน | ดูสถานะงานสแกน | ตรวจผลสำเร็จ ล้มเหลว หรือกำลังทำงาน |
| ไฟล์ในระบบ | จัดเก็บไฟล์ส่วนกลาง | อัปโหลด เปลี่ยนชื่อ ลบ ค้นหา |
| กระจายไฟล์ | สร้างงานส่งไฟล์ | เลือกไฟล์ เลือกเครื่อง/ห้อง ยืนยัน |
| ติดตามการกระจาย | ดูงานส่งไฟล์ | ค้นหา กรองสถานะ ดูรายละเอียด |
| ผู้ใช้งาน | จัดการบัญชี | เพิ่ม แก้ไข ลบ และเปลี่ยน Role/สถานะ |
| บทบาทและสิทธิ์ | กำหนดสิทธิ์ | เพิ่มหรือแก้ Role และเลือก Permission |
| Tokens | ออก Token ลงทะเบียน | สร้าง แก้เงื่อนไข ยุติการใช้งาน |
| Audit Logs | ตรวจประวัติ | กรองและเปิดรายละเอียดรายการ |
| ตั้งค่า | จัดการบัญชีตนเอง | ดูข้อมูล เปลี่ยนรหัสผ่าน จัดการ Session |

เมนูที่มองเห็นได้อาจแตกต่างกันตามสิทธิ์ของบัญชี หากกดหน้าใดแล้วพบ **ไม่มีสิทธิ์** ให้ติดต่อผู้ดูแล ไม่ควรพยายามแก้ URL เอง

## 6. แดชบอร์ด

หน้าแดชบอร์ดเป็นหน้าสรุป ไม่ใช่หน้าสำหรับแก้ข้อมูลโดยตรง การ์ดหลักแสดง

- **Agents:** จำนวนเครื่องทั้งหมดและจำนวนที่ออนไลน์
- **Rooms:** จำนวนห้องที่ระบบรู้จัก
- **Tokens:** จำนวน Token ที่ยังใช้งานได้เทียบกับทั้งหมด
- **กิจกรรม 24 ชั่วโมง:** จำนวน Audit Logs ในช่วง 24 ชั่วโมงล่าสุด

ส่วน **สถานะ Agents** แบ่งเป็น Online, Offline, Warning และ Disabled เพื่อให้เห็นภาพว่าเครื่องพร้อมใช้งานกี่เครื่อง ส่วน **ผู้ใช้งานและพื้นที่** แสดงจำนวนบัญชี Active, Disabled, Locked และจำนวนห้อง

ส่วน **ความปลอดภัย** สรุปจำนวนงาน Antivirus, งานที่เสร็จ และภัยคุกคามที่พบ ส่วนท้ายของหน้าจอจะแสดงกิจกรรมล่าสุดหรือรายการที่เพิ่งใช้งาน ให้ใช้หน้านี้เป็นจุดเริ่มต้นตรวจสุขภาพระบบก่อนสั่งงานใด ๆ

ถ้าตัวเลขเป็นศูนย์ ให้แยกให้ออกว่า “ไม่มีข้อมูลจริง” หรือ “Backend โหลดไม่ได้” หากมีข้อความผิดพลาด ควรกดรีเฟรชหรือตรวจการเชื่อมต่อก่อนสรุปว่าไม่มีเครื่อง

## 7. จัดการห้องเรียน

ห้องเป็นกลุ่มสำหรับจัดระเบียบเครื่อง ไม่ใช่ห้องแชต ตัวอย่างเช่น `ห้องคอม 1`, `LAB-A` หรือ `ชั้น 3 แผนกบัญชี`

### เพิ่มห้อง

1. เปิดเมนู **ห้องเรียน**
2. กด **เพิ่มห้อง**
3. กรอก **ชื่อห้อง** ซึ่งต้องไม่เกิน 100 ตัวอักษรและไม่ซ้ำกับห้องเดิม
4. กรอก **รายละเอียด** ได้ตามต้องการ เช่น อาคารหรือผู้รับผิดชอบ ช่องนี้เว้นว่างได้
5. กด **บันทึก**

### แก้ไขหรือลบห้อง

ใช้ช่องค้นหาชื่อหรือรายละเอียดเพื่อหาห้อง จากนั้นกด **แก้ไข** แล้วบันทึกข้อมูลใหม่ หากต้องการลบให้กด **ลบ** และยืนยัน

ควรตรวจสอบก่อนลบว่ามี Agent อยู่ในห้องหรือไม่ การลบห้องอาจถูก Backend ปฏิเสธหรือทำให้เครื่องกลายเป็น “ยังไม่ได้จัดห้อง” ขึ้นอยู่กับกฎของระบบ หากไม่แน่ใจให้ย้าย Agent ออกก่อน

## 8. จัดการ Agents

Agent คือโปรแกรมที่ติดตั้งอยู่บนเครื่องปลายทางและทำหน้าที่รับคำสั่ง/ส่งสถานะกลับมายังระบบ หน้ารายการจะแสดงชื่อเครื่อง ห้อง MAC Address, IP Address, ระบบปฏิบัติการ สถานะ และเวลาที่พบล่าสุด

สถานะที่พบได้

- **ออนไลน์ (ONLINE):** ระบบติดต่อเครื่องได้และเหมาะสำหรับสั่งงาน
- **ออฟไลน์ (OFFLINE):** ยังติดต่อไม่ได้ อาจปิดเครื่อง หลุดเครือข่าย หรือ Agent ไม่ทำงาน
- **มีคำเตือน (WARNING):** มีสถานะผิดปกติ ควรตรวจสอบก่อนสั่งงาน
- **ปิดใช้งาน (DISABLED):** ไม่ควรใช้เป็นเป้าหมายการสั่งงาน

### ค้นหาและแบ่งหน้า

ใช้ช่องค้นหาโดยพิมพ์ชื่อเครื่อง MAC, IP หรือระบบปฏิบัติการ ระบบจะแสดงรายการตามคำค้น กำหนดจำนวนรายการต่อหน้าได้ที่ **รายการต่อหน้า** และใช้ **ก่อนหน้า/ถัดไป** เมื่อมีหลายหน้า

### แก้ไข Agent

1. กด **แก้ไข** ในแถวของเครื่อง
2. แก้ **ชื่อเครื่อง** หากจำเป็น
3. เลือก **ห้องที่ติดตั้ง** หรือเลือก “ยังไม่ได้จัดห้อง”
4. IP และ MAC เป็นข้อมูลจากระบบและแก้จากหน้านี้ไม่ได้
5. กด **บันทึก**

### ดูรายละเอียดและลบ Agent

กด **รายละเอียด** เพื่อเปิดหน้ารายละเอียดของ Agent ใช้สำหรับดูข้อมูลเชิงลึกของเครื่อง หากกด **ลบ** ระบบจะแจ้งเตือนว่าคำสั่งที่เกี่ยวข้องจะถูกลบด้วย และไม่สามารถย้อนกลับได้ จึงควรลบเฉพาะ Agent ที่ยืนยันแล้วว่าไม่ใช้งานจริง

## 9. ตรวจสอบหน้าจอ Agents

หน้านี้ใช้ดูภาพหน้าจอของ Agent แบบ View-only ไม่มีการควบคุมเมาส์ คีย์บอร์ด หรือสั่งงานจากหน้าจอนี้

1. เปิดเมนู **ตรวจสอบหน้าจอ**
2. เลือกการ์ดห้องที่ต้องการตรวจ
3. ระบบจะแสดงจำนวนหน้าจอในห้องและสถานะการเชื่อมต่อ Socket
4. รอจนป้ายขึ้น **Socket เชื่อมต่อแล้ว** และภาพขึ้นสถานะ Live
5. ถ้าต้องการดูห้องอื่น ให้เลือกการ์ดห้องใหม่

ความหมายของสถานะ

- **กำลังเชื่อมต่อ Socket:** ระบบกำลังเริ่มการรับภาพ
- **Socket เชื่อมต่อแล้ว:** ช่องทางรับข้อมูลพร้อม
- **Live:** มีภาพล่าสุดจากเครื่อง
- **Waiting:** Agent ออนไลน์แต่ยังรอภาพ
- **Offline:** เครื่องหรือ Agent ไม่ออนไลน์
- **กำลังเชื่อมต่อใหม่ / เชื่อมต่อ Socket ไม่สำเร็จ:** ตรวจเครือข่ายและ WebSocket

เมื่อเปลี่ยนห้อง ระบบจะหยุดรับภาพจากห้องเดิม และเริ่มรับภาพจากห้องใหม่ ภาพที่เห็นเป็นข้อมูล ณ ขณะนั้น ไม่ใช่การบันทึกวิดีโอ

## 10. สั่ง AV Scan

ฟังก์ชันนี้ใช้ส่งคำสั่งตรวจหาไวรัสไปยัง Agent ที่พร้อมทำงาน ควรวางแผนเวลา โดยเฉพาะ Full Scan ที่อาจใช้ทรัพยากรและทำให้เครื่องช้าลง

### 10.1 เลือกประเภทการสแกน

- **Quick Scan:** ตรวจพื้นที่สำคัญและจุดที่มักพบภัยคุกคาม เหมาะสำหรับตรวจเบื้องต้น
- **Custom Scan:** ตรวจไฟล์หรือโฟลเดอร์ที่ระบุ ต้องระบุเส้นทาง Windows แบบเต็มเพียง 1 เส้นทาง เช่น `C:\Downloads` หรือ `\\server\share`
- **Full Scan:** ตรวจไฟล์และพื้นที่ทั้งหมดของเครื่อง ใช้เวลานานและทรัพยากรมาก

Custom Scan ห้ามใช้ wildcard เช่น `*` หรือ `?` และไม่สามารถใส่หลายเส้นทางในงานเดียวกัน

### 10.2 เลือกเป้าหมาย

มีสองวิธี

**สแกนทั้งห้อง**

1. เลือก **สแกนทั้งห้อง**
2. เลือกห้องที่ต้องการ
3. ดูจำนวนเครื่องทั้งหมด ออนไลน์ และไม่พร้อม
4. ระบบจะส่งคำสั่งเฉพาะเครื่องที่เป็น ONLINE ส่วน OFFLINE, WARNING และ DISABLED จะถูกข้าม

**เลือกเป็นรายเครื่อง**

1. เลือก **เลือกเป็นรายเครื่อง**
2. ค้นหาด้วยชื่อเครื่องหรือ IP ได้
3. กรองตามห้องได้ รวมถึง “ยังไม่ได้จัดห้อง”
4. ติ๊กเฉพาะเครื่องที่เป็นออนไลน์ หรือกดเลือกเครื่องออนไลน์ที่แสดงทั้งหมด
5. หากเลือกผิดให้กด **ล้างที่เลือก**

หนึ่งงานเลือกได้ 1–100 เครื่องเท่านั้น หากเกิน 100 เครื่องให้แบ่งเป็นหลายงาน

### 10.3 ยืนยันการสแกน

1. ตรวจส่วน **สรุปการสแกน** ได้แก่ ประเภท เป้าหมาย จำนวนพร้อมสแกน และจำนวนที่ถูกข้าม
2. กด **เริ่มสแกน**
3. อ่านรายชื่อเครื่องในหน้าต่างยืนยันอีกครั้ง
4. กด **ยืนยันสั่งสแกน**
5. ระบบจะพาไปหน้า **ติดตามผลการสแกน**

หากระบบแจ้งว่า “คำสั่งล่าสุดยังไม่ได้รับการยืนยัน” อย่ากดสั่งซ้ำทันที ให้ไปตรวจประวัติผลสแกนก่อน เพราะงานอาจถูกสร้างแล้วแต่การตอบกลับขัดข้อง

## 11. ติดตามผล AV Scan

เปิดเมนู **ติดตามผลการสแกน** เพื่อดูประวัติงานสแกนและผลจากเครื่องปลายทาง หน้านี้ใช้แยกสถานะว่างานกำลังดำเนินการ เสร็จแล้ว ล้มเหลว หรือพบภัยคุกคาม

เมื่อไม่เห็นผลล่าสุด ให้รอสักครู่แล้วรีเฟรชข้อมูล ตรวจว่าระบบเชื่อมต่ออยู่ และตรวจสถานะ Agent ของเครื่องนั้นด้วย การไม่พบข้อมูลทันทีไม่ควรตีความว่าเครื่องปลอดภัยแล้ว

แนวทางปฏิบัติเมื่อพบภัยคุกคาม

1. จดชื่อเครื่อง เวลา และผลสแกน
2. แยกเครื่องดังกล่าวออกจากการใช้งานตามนโยบายองค์กร
3. ให้ผู้รับผิดชอบด้านความปลอดภัยตรวจสอบรายละเอียด
4. สแกนซ้ำหลังแก้ไข และเก็บ Audit Log/ผลสแกนไว้เป็นหลักฐาน

## 12. จัดการไฟล์ในระบบ

เมนู **ไฟล์ในระบบ** คือคลังไฟล์ที่ใช้เป็นต้นทางสำหรับการกระจายไฟล์ไปยัง Agent

### อัปโหลดไฟล์

1. เปิดเมนู **ไฟล์ในระบบ**
2. กดปุ่มลอยสำหรับอัปโหลดไฟล์
3. เลือกไฟล์จากเครื่อง
4. ตรวจชื่อและรอการอัปโหลดเสร็จ
5. ตรวจว่ารายการไฟล์ปรากฏในหน้าคลัง

ไฟล์หนึ่งไฟล์ต้องมีขนาดไม่เกิน **100 MiB** หากใหญ่กว่านี้ระบบจะปฏิเสธ ควรตรวจว่าไฟล์เป็นไฟล์ที่ได้รับอนุญาตและไม่มีข้อมูลสำคัญเกินความจำเป็น

### ค้นหา เปลี่ยนชื่อ และลบ

- พิมพ์ในช่อง **ค้นหาไฟล์ในหน้านี้** เพื่อกรองรายการ
- กด **เปลี่ยนชื่อไฟล์** แล้วใส่ชื่อใหม่ จากนั้นกดบันทึก
- กด **ลบ** และยืนยันเมื่อต้องการนำไฟล์ออกจากคลัง
- ใช้ **รายการต่อหน้า** และ **ก่อนหน้า/ถัดไป** เมื่อมีหลายรายการ

การเปลี่ยนชื่อในคลังอาจมีผลต่อการเลือกไฟล์ครั้งถัดไป แต่ไม่ใช่การแก้ชื่อไฟล์ที่อยู่บนเครื่องปลายทางที่เคยรับไฟล์ไปแล้ว

## 13. กระจายไฟล์ไปยังเครื่อง

การกระจายไฟล์ประกอบด้วย 4 ขั้นตอน: เลือกไฟล์ เลือกประเภทเป้าหมาย เลือกปลายทาง และยืนยัน

### สร้างงาน

1. เปิดเมนู **กระจายไฟล์**
2. เลือกไฟล์จากคลัง หากไม่มีไฟล์ให้กลับไปอัปโหลดที่ **ไฟล์ในระบบ** ก่อน
3. เลือกประเภทปลายทาง
   - **เลือกเครื่อง:** ส่งไปยังเครื่องที่เลือกเป็นรายเครื่อง
   - **เลือกห้อง:** ส่งไปยังทุกเครื่องในห้องนั้น
4. ใช้ช่องค้นหาเพื่อหาเครื่องหรือห้อง
5. ตรวจสถานะปลายทางและจำนวนเครื่องที่จะได้รับไฟล์
6. เลือกประเภทปลายทางและรายละเอียดปลายทางตามที่ระบบแสดง
7. กดปุ่มสร้าง/ดำเนินการต่อ
8. อ่านหน้าต่าง **ยืนยันการกระจายไฟล์** ให้ครบ แล้วกดยืนยัน

ควรส่งไฟล์ไปยังเครื่องที่ออนไลน์เท่านั้น เครื่องออฟไลน์อาจถูกแสดงเป็น OFFLINE และไม่สามารถรับไฟล์ได้ทันที ระบบจะรายงานผลแยกตามเครื่อง อย่าสร้างงานซ้ำเพียงเพราะบางเครื่องยังไม่เสร็จ

### ตรวจความคืบหน้า

หลังยืนยัน ระบบจะสร้าง Distribution Job และแจ้งว่ากำลังให้ Backend สร้างงาน เปิดเมนู **ติดตามการกระจาย** เพื่อดูความคืบหน้า

สถานะของงานโดยทั่วไป

- **กำลังดำเนินการ:** ยังมีเครื่องที่กำลังรับหรือประมวลผล
- **สำเร็จ:** ปลายทางสำเร็จครบตามงาน
- **สำเร็จบางส่วน:** บางเครื่องสำเร็จ บางเครื่องล้มเหลวหรือออฟไลน์
- **ไม่สำเร็จ:** งานไม่สำเร็จ

สถานะปลายทางอาจเป็น Pending, Downloading, Verifying, Completed, Failed, Offline หรือ Cancelled ให้เปิด **ดูรายละเอียด** เพื่อดูเครื่องใดสำเร็จ เครื่องใดล้มเหลว และสาเหตุที่ระบบรายงาน

## 14. ติดตามการกระจายไฟล์

หน้านี้แสดงชื่อไฟล์ รหัสงาน ปลายทาง แถบความคืบหน้า จำนวนสำเร็จ จำนวนล้มเหลว จำนวนออฟไลน์ สถานะ และเวลาสร้าง

ใช้ช่องค้นหาได้จากชื่อไฟล์ รหัสงาน หรือห้อง และใช้ตัวกรองสถานะ ได้แก่ ทุกสถานะ กำลังดำเนินการ สำเร็จ สำเร็จบางส่วน และไม่สำเร็จ จากนั้นกด **ค้นหา** หากต้องการกลับมาแสดงทั้งหมดให้กด **ล้างตัวกรอง**

กด **ดูรายละเอียด** เพื่อเรียงหรือค้นหาเครื่องในงานนั้น หากงานค้างนาน ให้ตรวจสถานะ Agent และการเชื่อมต่อ WebSocket ก่อนสร้างงานใหม่

## 15. จัดการผู้ใช้งาน

เมนู **ผู้ใช้งาน** ใช้สำหรับผู้ดูแลระบบเท่านั้น ตารางแสดงผู้ใช้งาน Role สถานะ และการเข้าสู่ระบบล่าสุด

### เพิ่มผู้ใช้

1. กด **เพิ่มผู้ใช้งาน**
2. กรอก **ชื่อผู้ใช้**
3. กรอก **ชื่อที่แสดง**
4. กรอก **อีเมล** หากมี
5. เลือก **Role** จากรายการที่ระบบให้
6. เลือกสถานะ โดยทั่วไปคือ `ACTIVE`, `DISABLED` หรือ `LOCKED`
7. ตั้งรหัสผ่าน
8. กดบันทึก

ชื่อผู้ใช้ควรมีความหมายและไม่ใช้บัญชีร่วมกันหลายคน เพราะ Audit Logs จะระบุผู้กระทำตามบัญชี

### แก้ไขและลบผู้ใช้

ใช้ช่องค้นหาชื่อ ชื่อผู้ใช้ อีเมล หรือ Role จากนั้นกด **แก้ไข** เพื่อเปลี่ยนข้อมูล Role สถานะ หรือรหัสผ่านใหม่ หากต้องการลบให้กด **ลบ** และอ่านคำยืนยันก่อนดำเนินการ

สถานะบัญชี

- `ACTIVE`: ใช้งานได้
- `DISABLED`: ผู้ดูแลปิดการใช้งาน
- `LOCKED`: ระบบหรือผู้ดูแลล็อกบัญชี อาจเกิดจากความปลอดภัยหรือการพยายามเข้าสู่ระบบผิดหลายครั้ง

อย่าลบบัญชี `admin` หลักจนกว่าจะมีบัญชีผู้ดูแลสำรองที่ทดสอบเข้าใช้งานได้แล้ว

## 16. บทบาทและสิทธิ์

Role คือชุดสิทธิ์ที่ผูกกับผู้ใช้งาน เช่น Administrator หรือ Operator ส่วน Permission คือความสามารถย่อยของระบบ เช่น อ่านหรือจัดการห้อง ไฟล์ หรือผู้ใช้งาน

### เพิ่มหรือแก้ Role

1. เปิดเมนู **บทบาทและสิทธิ์**
2. กด **เพิ่มบทบาท** หรือกด **แก้ไข** ที่การ์ด Role เดิม
3. ระบุ **ชื่อบทบาท** สูงสุด 50 ตัวอักษร และห้ามซ้ำ
4. ใส่คำอธิบายหน้าที่ของบทบาทได้
5. ติ๊ก Permission รายการที่ต้องการ หรือกด **เลือกทั้งหมด**
6. สามารถเลือก/ยกเลิกทั้งกลุ่มได้จากช่องหน้าชื่อกลุ่ม
7. ตรวจจำนวน “เลือกแล้ว” ให้เหมาะกับหน้าที่
8. กด **เพิ่มบทบาท** หรือ **บันทึกการแก้ไข**

ระบบมีบทบาทหลักที่ไม่ควรลบ และ Backend อาจปฏิเสธการลบ Role ที่ยังมีผู้ใช้งานผูกอยู่ หากยังไม่มี Permission ในระบบ ปุ่มเพิ่ม Role จะใช้งานไม่ได้ ต้องให้ผู้ดูแล Backend จัดเตรียม Permission ก่อน

หลักการกำหนดสิทธิ์ที่ปลอดภัยคือให้เท่าที่จำเป็นต่อหน้าที่ ไม่ควรให้สิทธิ์ผู้ใช้งานทุกคนเป็น Administrator

## 17. Enrollment Tokens

Token ใช้เป็นรหัสสำหรับขั้นตอนลงทะเบียน Agent หรือการเชื่อมต่อประเภทที่ระบบกำหนด Token เป็นข้อมูลลับ ควรสร้างให้ตรงวัตถุประสงค์และกำหนดอายุ/จำนวนครั้งเสมอ

### สร้าง Token

1. เปิดเมนู **Tokens**
2. กด **สร้าง Token**
3. ระบุ **จำนวนครั้งสูงสุด** หากต้องการจำกัด เช่น `10`
4. ระบุ **วันหมดอายุ** หากต้องการให้หมดอายุอัตโนมัติ
5. เว้นว่างได้หากต้องการไม่จำกัด แต่ไม่แนะนำสำหรับงานจริง
6. กด **สร้าง Token**
7. เมื่อกล่อง **สร้าง Token สำเร็จ** แสดงค่าเต็ม ให้กด **คัดลอก** และเก็บไว้ในที่ปลอดภัยทันที

ค่าของ Token จะแสดงเต็มเฉพาะตอนสร้าง ไม่ควรปิดกล่องก่อนคัดลอก และไม่ควรใส่ในภาพหน้าจอหรือเอกสารสาธารณะ

### ตรวจ แก้ และยุติ Token

- ใช้ช่องค้นหา ID ประเภท หรือผู้สร้าง
- กด **รายละเอียด** เพื่อดูผู้สร้าง จำนวนครั้งที่ใช้ วันหมดอายุ และสถานะ
- กด **แก้ไข** เพื่อเปลี่ยน `max_use` หรือ `expires_at`
- กด **ยุติการใช้งาน** เมื่อ Token รั่วไหล ใช้เสร็จ หรือไม่ต้องการให้ใช้ต่อ

การยุติ Token เป็นการดำเนินการถาวรและกู้คืนไม่ได้ รายการประวัติยังคงอยู่เพื่อการตรวจสอบ

## 18. Audit Logs

Audit Logs คือหลักฐานกิจกรรมของระบบ เช่น การเข้าสู่ระบบ การสร้าง แก้ไข ลบ และคำขอที่ล้มเหลว ระบบแสดงรายการใหม่สุดก่อน เวลาในตารางเป็นเวลาไทย

### กรองประวัติ

ตัวกรองที่มีให้ใช้ ได้แก่

- **ผู้กระทำ (UUID):** จำกัดตามรหัสผู้ใช้
- **เครื่องเป้าหมาย (UUID):** จำกัดตามรหัส Agent
- **Action:** ต้องตรงทั้งค่า เช่น `POST /api/rooms/`
- **จำนวนรายการต่อหน้า:** 20, 50 หรือ 100 รายการ

กรอกตัวกรองแล้วกด **ค้นหา** หากต้องการเริ่มใหม่กด **ล้างตัวกรอง** กด **รีเฟรช** เพื่อดึงข้อมูลล่าสุด

ในตารางจะเห็นเวลา ผู้กระทำ Action เครื่องเป้าหมาย ผล HTTP, IP Address และปุ่ม **ดูรายละเอียด** ผล HTTP เป็นผลของคำขอที่บันทึก ไม่ได้หมายความว่างานบนเครื่องปลายทางเสร็จสมบูรณ์แล้ว

### อ่านรายละเอียด

กด **ดูรายละเอียด** เพื่อดูรหัสรายการ ผู้กระทำ เวลา User ID, Agent ID, IP และข้อมูล Detail แบบเต็ม หากพบคำขอผิดพลาดซ้ำ ๆ ให้เก็บเวลา IP และ Action แล้วส่งให้ผู้ดูแลตรวจสอบ

ข้อควรรู้เกี่ยวกับการเก็บ Log: ระบบอาจเก็บข้อมูลเริ่มต้นประมาณ 90 วัน ลบข้อมูลเก่าอย่างถาวรเป็นรอบ และมีการลดรายการข้อผิดพลาดซ้ำในช่วงเวลาสั้น ๆ ดังนั้นจำนวนรายการอาจไม่เท่ากับจำนวนครั้งที่เหตุการณ์เกิดขึ้นทั้งหมด

## 19. ตั้งค่าบัญชีของฉัน

เปิดจากชื่อบัญชีด้านล่างซ้าย > **ตั้งค่า** หน้านี้จะแสดงชื่อผู้ใช้ ชื่อที่แสดง อีเมล และสิทธิ์ของบัญชีที่กำลังเข้าสู่ระบบ

### เปลี่ยนรหัสผ่าน

1. กรอกรหัสผ่านปัจจุบัน
2. กรอกรหัสผ่านใหม่
3. กรอกยืนยันรหัสผ่านใหม่ให้ตรงกัน
4. กดปุ่มเปลี่ยนรหัสผ่าน
5. เตรียมเข้าสู่ระบบใหม่บนอุปกรณ์ต่าง ๆ เพราะเมื่อเปลี่ยนสำเร็จทุกอุปกรณ์จะต้องเข้าสู่ระบบใหม่

ใช้รหัสผ่านที่ไม่ซ้ำกับระบบอื่น ยาวพอสมควร และไม่ใช้ข้อมูลเดาง่าย เช่น ชื่อหรือวันเกิด

### จัดการ Session

ส่วน Session ใช้ตรวจสอบและนำ Session ที่ไม่รู้จักออกจากระบบ หากสงสัยว่าบัญชีถูกใช้จากเครื่องอื่น ให้กดออกจาก Session ที่ไม่รู้จัก หรือใช้ **ออกจากระบบทุกอุปกรณ์** แล้วเปลี่ยนรหัสผ่านทันที

## 20. แนวทางการใช้งานประจำวัน

ลำดับการทำงานที่แนะนำสำหรับผู้ดูแล

1. เข้าสู่ระบบด้วยบัญชีส่วนตัว ไม่ใช้บัญชีร่วม
2. ดู Dashboard ตรวจจำนวน Online และกิจกรรมผิดปกติ
3. ตรวจ Agents ที่มี Warning หรือ Offline
4. ตรวจห้องและการจัดกลุ่มให้ตรงกับสถานที่จริง
5. ก่อนสั่ง AV Scan หรือกระจายไฟล์ ให้ตรวจรายชื่อเป้าหมายซ้ำ
6. สั่งงานช่วงเวลาที่เหมาะสม โดยเฉพาะ Full Scan และการส่งไฟล์จำนวนมาก
7. เปิดหน้าติดตามผลเพื่อยืนยันผล ไม่ถือว่าการกดปุ่มคือการทำงานเสร็จ
8. ตรวจ Audit Logs เมื่อมีเหตุผิดปกติ
9. ออกจากระบบเมื่อใช้งานเสร็จ

## 21. การแก้ปัญหาเบื้องต้น

### หน้าเว็บเปิดไม่ได้

ตรวจ URL, ตรวจว่า Next.js ทำงานอยู่ ตรวจพอร์ต 3000 และตรวจว่าเครือข่ายเข้าถึงเครื่องเซิร์ฟเวอร์ได้ หากรันในเครื่องพัฒนาให้ลอง `npm run dev` ใหม่

### ล็อกอินแล้วเด้งกลับหน้า Login

ตรวจ Backend, Session Cookie, วันเวลาเครื่อง และ URL ให้ใช้โดเมนเดียวกันตามที่ผู้ดูแลกำหนด ลองปิดเปิดเบราว์เซอร์หรือเข้าสู่ระบบใหม่ หากยังเป็นให้ผู้ดูแลตรวจ Log ของ Auth API

### หน้าโหลดได้แต่ไม่มีข้อมูล

กดรีเฟรช ตรวจการเชื่อมต่อ Backend และตรวจสิทธิ์ของบัญชี ถ้ามีข้อความ “โหลดข้อมูลไม่สำเร็จ” ให้จดข้อความนั้นไว้ ไม่ควรลบหรือสร้างข้อมูลซ้ำทันที

### Agent ขึ้น Offline

ตรวจว่าเครื่องเปิดอยู่ เชื่อมต่อเครือข่ายได้ โปรแกรม Agent ทำงานอยู่ และ Backend/WebSocket เข้าถึงได้ หากเพิ่งเปิดเครื่องให้รอสักครู่แล้วรีเฟรช

### ดูหน้าจอไม่ขึ้น

เลือกห้องให้ถูก รอ Socket ตรวจว่า Agent Online และตรวจ `NEXT_PUBLIC_FRONTEND_WS_URL`/เครือข่าย WebSocket หากขึ้น Reconnecting แสดงว่าระบบกำลังพยายามเชื่อมต่อใหม่

### สั่งสแกนไม่ได้

ต้องมีการเชื่อมต่อแบบ Live เลือกเครื่องออนไลน์อย่างน้อย 1 เครื่อง และไม่เกิน 100 เครื่อง หากเป็น Custom ต้องใส่เส้นทางเต็ม 1 เส้นทางโดยไม่มี wildcard ถ้าระบบแจ้งคำสั่งไม่ยืนยัน ให้ตรวจผลก่อนสั่งซ้ำ

### กระจายไฟล์ค้างหรือไม่สำเร็จ

เปิดรายละเอียดงาน ตรวจเครื่องที่เป็น Offline/Failed ตรวจว่าไฟล์ต้นทางยังอยู่ในคลัง และตรวจการเชื่อมต่อของ Agent หากบางเครื่องสำเร็จแล้ว ไม่ควรส่งซ้ำทั้งห้องโดยไม่ตรวจรายเครื่องก่อน

### Token ใช้ไม่ได้

ตรวจ Token ยังไม่หมดอายุ ไม่ถูกยุติ จำนวนครั้งยังไม่เต็ม และคัดลอกค่าโดยไม่มีช่องว่าง หากสงสัยว่าค่ารั่วไหล ให้ยุติ Token เดิมแล้วสร้างใหม่

### พบข้อความไม่มีสิทธิ์

บัญชีไม่มี Permission สำหรับงานนั้น ติดต่อผู้ดูแลให้ตรวจ Role และสิทธิ์ อย่าใช้บัญชี Administrator ของผู้อื่นแทนโดยไม่บันทึกเหตุผล

## 22. คำศัพท์สำคัญ

| คำศัพท์ | ความหมาย |
|---|---|
| Agent | โปรแกรมบนเครื่องปลายทางที่เชื่อมต่อกับ Dashboard |
| Backend | ระบบบริการเบื้องหลังที่เก็บข้อมูลและรับคำสั่ง |
| Room | กลุ่มของ Agent ตามห้อง/สถานที่ |
| Online | Agent ติดต่อระบบได้ในขณะตรวจล่าสุด |
| View-only | ดูข้อมูลได้ แต่ไม่ควบคุมเครื่องจากหน้านั้น |
| AV Scan | การตรวจ Antivirus |
| Token | ค่าลับสำหรับการลงทะเบียน/ยืนยันตามที่ระบบกำหนด |
| Role | ชุดของ Permission ที่กำหนดให้ผู้ใช้ |
| Permission | สิทธิ์ย่อยสำหรับการอ่านหรือจัดการทรัพยากร |
| Session | สถานะการเข้าสู่ระบบของอุปกรณ์หนึ่งเครื่อง |
| Audit Log | ประวัติกิจกรรมที่ระบบบันทึกไว้ |
| WebSocket | ช่องทางสื่อสารแบบต่อเนื่องสำหรับข้อมูลสด |
